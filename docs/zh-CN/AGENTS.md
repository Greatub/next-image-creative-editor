# AGENTS.md · 协作开发规则

最后更新：2026-10-23

[English](../../AGENTS.md) | [简体中文](AGENTS.md)

本文件写给所有参与 NICE 开发的 agent（以及人）。开始任何工作前请完整读完。

## 1. 真相来源（冲突时按此优先级）

1. [decisions.md](../../docs/decisions.md) —— 已定决策，最高优先级
2. [product.md](../../docs/product.md)、[ui-spec.md](../../docs/ui-spec.md)、[architecture.md](../../docs/architecture.md)、[data-model.md](../../docs/data-model.md)
3. `../../design/tokens.json`
4. `../../design/prototype/` 里的设计稿 —— **只用于理解界面意图**；设计稿是演示原型，其中的示例数据、简化算法（例如用 CSS 滤镜模拟调色）不代表实现方式
5. 任何聊天记录或口头描述

如果文档之间互相矛盾，或文档与任务要求矛盾：**不要自行选边**。把问题写进 [open-questions.md](../../docs/open-questions.md)，在任务汇报里指出，然后停在那一步。项目负责人的明确新决策需记录替代关系，不删除历史决策；D-026 已记录本次英文优先的要求并替代 D-025 的语言规则。

## 2. 不可违反的产品约束

- **原始文件只读**：任何功能都不能修改 NEF / JPEG / HEIF 原文件。所有编辑都写参数文件或新导出的文件。
- **参数分层**（详见 [architecture.md](../../docs/architecture.md)）：
  - L1：尼康兼容参数 → `NKSC_PARAM/<文件名>.nksc`，NX Studio 可还原，兼容性仍需验证
  - L2：仅 NICE 生效的参数 → NICE 自己的边车文件 / 资料库
  - L3：导出时烘焙进新文件
  - 每个新功能都必须声明自己属于哪一层，并在界面上标注（"NX Studio 可还原" / "仅 NICE"）。
- **一个功能只有一个位置**：新增功能前先查 [ui-spec.md](../../docs/ui-spec.md) 的「功能唯一位置表」；若已有入口，复用而不是新建。
- **防抖动**：四个页面共享同一骨架（标题栏 48px、左右栏各 300px、底栏 108px、照片区边距 32px）。新增内容只能放进面板内部，不得改变骨架尺寸。
- **来源只在浏览页选择**：底栏左侧只显示当前来源，不可点击。
- **照片区保持干净**：照片上方只允许右下角的显示方式控件，以及临时状态提示（如 100% 缩放提示）。

## 3. 工作流程

1. 接到任务 → 读本文件 → 读 [decisions.md](../../docs/decisions.md) → 读与任务相关的规范章节。
2. 若任务需要新增或改变产品行为：先在 [open-questions.md](../../docs/open-questions.md) 提出，由项目负责人确认并记入 [decisions.md](../../docs/decisions.md) 后再实现。
3. 实现完成后：
   - 更新受影响文档的「最后更新」日期和内容；
   - 若做出了新的技术决定（库、格式、目录结构），在 [decisions.md](../../docs/decisions.md) 追加一条，状态写「提议」，等待确认。
4. 不删除他人的文件或决策记录；需要废弃时标注「已废弃」并说明原因和替代项。
5. 修改前检查当前分支和工作区；不在 `main` 直接开发，每个功能使用独立分支。先说明计划，完成后汇报修改文件、验证与风险。

## 4. 文档与代码约定

- 文档语言：英文为主、简体中文为辅（D-026）；默认英文资料为维护基准，完整中文译文放在 `../../docs/zh-CN/`，更新时双向链接并同步内容。代码、标识符、文件名、提交信息使用英文。
- 术语统一使用 [glossary.md](../../docs/glossary.md) 中的叫法（例如：用「相册」，不用「影集 / 标签」；用「显示方式」指 标准 / 专注 / 沉浸）。
- 决策编号格式 `D-001`，问题编号格式 `Q-001`，需求编号见 [product.md](../../docs/product.md)（如 `BR-03`）。
- 颜色、尺寸、动效时长一律引用 `../../design/tokens.json` 中的令牌名，不在代码里写死。
- 技术选型尚未确定（见 `Q-001`），在确定前不要建立 `src/` 目录或引入框架。

- 不提交 API 密钥、令牌、私有配置或真实用户数据；本地环境变量使用 `.env` / `.env.local`。浏览器扩展权限遵循最小权限原则。
- 未明确要求时，不重写项目结构、不移除现有功能、不生成无关样板代码；引入框架前说明用途。

## 5. 品牌资产

- `../../App Icon/` 是定稿图标，`../../SVG Icon/` 是设计备选稿。**不要修改、移动或重新导出**；需要新尺寸时在 [open-questions.md](../../docs/open-questions.md) 提出。
- 软件名：NICE（全称 Next Image Creative Editor），界面中统一写作大写 `NICE`。未经明确要求，不修改标志、品牌色或产品名。

## 6. 验收时自查清单

- [ ] 原始文件未被写入
- [ ] 新参数已声明 L1 / L2 / L3，并在界面上标注
- [ ] 没有新增重复入口（对照功能唯一位置表）
- [ ] 骨架尺寸未变，四个页面切换无位移
- [ ] 深色与中性灰两套主题下文字对比度 ≥ 4.5:1
- [ ] 所有可点击元素是真实的按钮 / 链接 / 表单控件，有可读的名称
- [ ] 拖放操作都有等效的点击方式

- [ ] 英文与中文文档已同步。
