## 尼康兼容性（开发前必须验证）

| 编号 | 问题 | 为什么重要 | 状态 / 建议 |
|---|---|---|---|
| Q-002 | `.nksc` 能否由第三方可靠读写，NX Studio 是否接受 | 核心卖点 | **在 NX Studio 1.11（macOS）上可行**（2026-10-23）。文件是 XMP 文本包，编辑内容在经 XML 转义的滤镜清单中。NICE 写入的曝光和评分修改被 NX Studio 正确读取。白平衡与优化校准使用二进制子块，已部分解出。见 [research/nksc-format.md](research/nksc-format.md)。仍需测试：其他 NX Studio 版本、Windows 版、Capture NX-D |
| Q-003 | `.nksc` 写入未知数据的后果；L2 效果能否降级为 L1 近似（如负片用反向曲线） | 决定 L2 存放与降级策略 | 部分有答案：放在 `rdf:Description` 中的自定义命名空间元素**在 NX Studio 1.11 重新保存后被保留**（一次测试）。建议：L2 仍按设计单独存为 `.nice`（D-003），一个版本的行为不能当作保证；可以只在 `.nksc` 中写一个小的 NICE 标记。L2 降级为 L1 近似尚未测试 |
| Q-005 | 评分 / 色标存放位置及与 NX Studio 互通 | 选片结果要在两个软件间一致 | 评分已明确：存放在 `.nksc` 内嵌的 XMP 包中（`xmp:Rating` + `MicrosoftPhoto:Rating`），NICE 写入的 5 星在 NX Studio 中正确显示；`nine:Rating` 不使用。色标（`nine:Label`）尚未测试 |
| Q-006 | NX Studio 是否读取 NICE 写入的 XMP/IPTC 层级关键字 | 相册写入关键字的价值 | 未验证 |
| Q-007 | 自定义优化校准（NP3）导出可行性 | 让 NICE 风格回到相机，差异化功能 | 未验证，非 v1 必需 |
| Q-016 | NICE 渲染 L1 参数的结果能否与 NX Studio 一致（暗角与畸变的镜头校正、优化校准色调曲线、动态 D-Lighting、白平衡）？「NX Studio 能读取参数」与「NICE 渲染效果一致」是两件事 | 「NX Studio 可还原」的标注暗含两个软件的显示效果一致 | 部分解答（2026-10-23），见 [research/render-parity.md](research/render-parity.md)。以 NX Studio 1.11 导出的 `DSC_3183` 为标准：LibRaw 直接渲染 ΔE2000 平均约 14；模拟镜头几何、暗角、色调曲线和色彩矩阵后，低频平均约 1.8（样本内），而机内 JPEG 与 NX Studio 之间约 0.6。这种做法做不到像素级一致，但经过标定有望「肉眼接近」。最大差距依次是：默认色调（优化校准曲线 / 基准曝光 / 动态 D-Lighting）、畸变、暗角。NX Studio 的曝光不是线性增益。NEF 内嵌一张全尺寸的尼康渲染预览。建议：「NX Studio 可还原」指参数而非像素；按「标定后接近尼康的默认效果」（选项 B）规划；尼康 SDK 渲染在 Q-004 中继续调查。需负责人决定：编辑前是否显示内嵌预览，还是始终显示 NICE 渲染。2026-10-24 补测：拍摄时动态 D-Lighting 为关闭，不是此处差距的来源；每种优化校准类型需单独标定（按类型拟合约 1.6–2.0，套用自动的模型最差 4.9）。这支镜头在 NX Studio 中无法关闭镜头校正。下一步：第二个场景、一张开启动态 D-Lighting 拍摄的 NEF |
| Q-017 | 尼康各优化校准类型下每个参数的取值范围是多少 | NX Studio 读取超出范围的值时不提示，只在重新保存时截断；NICE 绝不能写入无效值 | 待研究。已观察到：**自动**类型下对比度只能在 ±2 之间（NICE 写入的 −3 在 NX Studio 重新保存后被截断为 −2）。需要逐个参数、逐个类型测定。2026-10-24：已测得类型编号（0 自动、2 标准、3 中性、4 鲜艳、12 平面），并发现 `ExportData` 分两组存放——自动类型存相对调整（第 172–222 字节），固定类型存绝对值（第 82–132、242 字节），见 [research/nksc-format.md](research/nksc-format.md) 4.1 节。下一步：负责人记录 NX Studio 中各类型的默认滑块值，用来逐字节对应 |
